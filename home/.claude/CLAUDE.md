# Code comments
Keep comments short — one or two lines. Don't write multi-paragraph comment blocks explaining history, rationale, or cross-file reasoning inline; put that in the commit message or PR description instead.
This rule applies only to code written for me. When reviewing other people's code, don't flag or rewrite their comments for length.

# After plan mode
When a plan is approved (ExitPlanMode), implement it with the `review-loop` skill: build, review, fix, up to 4 cycles.
